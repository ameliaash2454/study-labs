
Имеется архив с файлами Журнал событий (.evtx) и .csv.

Вопросы, на которые необходимо ответить:
Какая операционная система у хоста, с которого был перехвачен сетевой трафик? 
Какова причина сбоя, связанная с журналами ошибок аудита? 
Какое имя пользователя локальной учетной записи, на которую направлена атака? 
Какой идентификатор события Windows связан с этими ошибками входа в систему? 
Какой IP-адрес источника проводит эту атаку? 
С какой страной связан этот IP-адрес?


**Тип работы:** учебное расследование инцидента · **Источник данных:** BTLO Bruteforce Challenge  
**Инструменты:** Excel, Power Query, Просмотр событий Windows  
**Техника MITRE ATT&CK:** T1110.001 — Password Guessing

## Краткий вывод

В предоставленном CSV обнаружены **3103 неудачные сетевые попытки входа** в учётную запись `administrator` с одного адреса — `113.161.192.227`. Записи относятся к периоду **12 февраля 2022 года, 06:26:43–07:22:00** (55 минут 17 секунд). Повторяемость попыток, общий источник и целевая учётная запись согласуются с попыткой подбора пароля. Подтверждения успешного входа с этого адреса в предоставленных событиях нет.
## Задача и материалы

Цель: определить источник и цель серии ошибок входа, оценить её интенсивность и проверить, появился ли после ошибок успешный вход атакуемой учётной записи.

## Методика

1. Импортировала CSV в Power Query в кодировке UTF-8 с разделителем «запятая». В рабочей копии добавил отсутствующий заголовок шестого столбца `Message`. Проверил, что многострочное сообщение каждого события остаётся в одной ячейке.
2. Сгруппировал события по `Event ID` и выделил ошибки входа `4625`.
3. Из текста `Message` извлёк `Account For Which Logon Failed → Account Name`, `Failure Reason`, `Logon Type`, `Source Network Address`, `Status` и `Sub Status`. 
4. Сгруппировал ошибки по IP и учётной записи; подсчитал число событий, первое и последнее время.
5. Отдельно проверил события успешного входа `4624`: сопоставил учётную запись, тип входа и сетевой адрес с серией ошибок.

### Серия ошибок входа

| Поле                      | Значение                             |
| ------------------------- | ------------------------------------ |
| Event ID / Keywords       | `4625` / `Audit Failure`             |
| Целевая учётная запись    | `administrator`                      |
| Source Network Address    | `113.161.192.227`                    |
| Число ошибок              | **3103**                             |
| Первая / последняя запись | **06:26:43 / 07:22:00**, 12.02.2022  |
| Интервал между записями   | **55 минут 17 секунд**               |
| Logon Type                | `3` — сетевой вход                   |
| Failure Reason            | `Unknown user name or bad password.` |
| Status / Sub Status       | `0xC000006D` / `0xC000006A`          |
| Authentication Package    | `NTLM`                               |

Sub Status `0xC000006A` уточняет причину как неверный пароль. Журнал не показывает сами проверявшиеся пароли. Тип входа `3` указывает на сетевую аутентификацию, но не определяет конкретный сетевой сервис.

При группировке по фиксированным пятиминутным интервалам серия затрагивает **12 интервалов**, в каждом зарегистрировано не менее десяти ошибок. Это подтверждает, что активность была продолжительной, а не состояла из нескольких случайных опечаток.

### Проверка успешных входов

В CSV есть четыре события `4624`, но во всех четырёх указан **`Logon Type 5`**, учётная запись **`NT AUTHORITY\SYSTEM`**, а `Source Network Address` не заполнен (`-`). Это служебные входы, связанные с запуском служб, а не подтверждение входа под `administrator` с исследуемого IP.

**Вывод по доступным данным:** попытки входа подтверждены; успешный вход атакующего в этом наборе событий **не обнаружен**. Вывод не распространяется на журналы и периоды, которые не были предоставлены.

### Дополнительная проверка IP

[IPinfo](https://ipinfo.io/113.161.192.227) связывает `113.161.192.227` с **Вьетнамом**. Геолокация относится к IP-адресу и сама по себе не устанавливает физическое местонахождение человека, инициировавшего попытки.

## Идея правила обнаружения

Для SIEM можно проверять **не менее 10 событий `4625` за 5 минут для одной пары «IP + учётная запись»**. После срабатывания аналитик сопоставляет последующие `4624` по тому же пользователю, источнику и периоду. На предоставленном CSV условие выполняется в 12 пятиминутных интервалах.

Порог здесь демонстрационный: перед использованием в рабочей среде его нужно сверить с обычным фоном аутентификации и проверить ложные срабатывания, например от неверно настроенной службы или устаревших учётных данных.
